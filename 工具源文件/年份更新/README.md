# 年份更新工具链

用来把工具更新到新一年的国考职位表。**2027 版就是用这套脚本做出来的。**

## 什么时候用

每年 10 月左右，新一年的国考职位表出来之后。

## 前提

- Node.js 可用（跑 `.js`）
- Python + `xlrd`（跑 `.py`；`gk-select` 的 .venv 里就有）
- **上一年的 html 版本还在**（脚本要拿它当模板 + 算同比）

## 三步走

改每个脚本顶部的 `CONFIG` 区（就两三个数字和路径），然后按顺序跑：

```bash
# 1. 解析新表 -> raw JSON
python 1-解析原始表.py

# 2. raw JSON -> 内嵌数据（gzip+base64），同时算好同比
node 2-生成内嵌数据.js

# 3. 套用上一年模板，生成新版 html
node 3-替换生成新版html.js            # 先预览，看清要替换哪些位置
node 3-替换生成新版html.js --apply    # 确认后真正生成
```

## 为什么这么设计

| 设计 | 原因 |
|---|---|
| 解析函数**从旧 html 里抽取**，不在脚本里重写 | 页面逻辑一改，脚本自动跟随，永远不会出现"脚本的算法和页面的算法不一样" |
| 第 3 步**默认只预览不写文件** | 年份替换是全局的，必须先看清楚会改到哪几处再落盘 |
| 替换年份用**单次扫描**而非链式替换 | 若先把 2025→2026、再把 2026→2027，会把刚生成的 2026 又变成 2027。单次扫描没这个问题 |
| 只动 base64 数据块 + 数据块外的年份文案 | 业务逻辑一行不碰，风险最小 |
| 自动校验字段集与上一年一致 | 字段对不上会直接报错中止，不会产出一个坏文件 |

## 产出

| 文件 | 说明 |
|---|---|
| `raw<年>.json` | 原始解析结果，中间产物 |
| `data<年>.b64` | 内嵌数据，中间产物 |
| `../国考选岗助手-<年>.html` | **最终产物** |

## 做完之后

1. 用浏览器打开新版抽查：条数对不对、点开岗位有没有分、控制台有没有报错
2. 跑回归（对照《技术档案》第七章的验收基线）
3. 检查`生成选岗报告.py` 会不会自动选到新版（它按文件名里的年份取最大）

## 2027 那次的实测数据

| 项 | 值 |
|---|---|
| 岗位数 | 20,714 → 19,426（−6.2%） |
| 招录人数 | 38,119 → 35,691（−6.4%） |
| 字段集 | 27 列，与 2026 **逐字节一致** |
| 需替换的年份文案 | 8 处（2026 ×3、2025 ×5） |
| 同比匹配率 | 54.79% → 59.05% |
| 是否需改专业对照表 | **不需要**（2027 无新类名，未识别率 1.18% vs 1.12%） |
